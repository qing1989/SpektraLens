## 更新提醒与弹窗

- `MainActivity.onStart()` 发起静默检查；后台任务不弹进度、不自动打开更新弹窗、不自动下载。正在检查、下载、安装，或已有更新弹窗时不重复检查。从未知来源设置返回且有待安装包时，先由现有 `resume()` 续接安装。
- 手动点击遇到正在进行的静默检查时共用该请求，显示可取消的进度，完成后再展示结果；无进行中的请求时手动重新获取清单。
- 只有远端 `versionCode` 更高且 `minSdk` 不超过当前 Android API 时，首页「关于」显示 `new`，关于页「检查更新」显示「可更新」。角标按实际字高预留空间，显示与隐藏不挪动按钮，不单独聚焦；角标区域也可点击原操作，禁用状态与按钮一致。
- 有效候选清单缓存在本机私有 `update_notice` preferences。网络失败、超时或清单损坏不清除上次已确认的提醒；未曾发现新版时失败也不显示角标。新进程按当前安装版本重新判定缓存，升级到目标或更高版本后自动清除。成功取到同版、旧版或不兼容的清单时也清除，以免提示已撤回或不能安装的版本。
- 查看更新说明或点「稍后」不消除提醒。两个入口由同一状态更新，关于页已经打开时也会同步。
- `UpdateNotesDialog` 使用可滚动正文与独立固定操作区；高度取内容所需高度与可用窗口高度 72% 中的较小值，宽度最多 480dp，保留左右边距。窗口大小变化时重新测量，正文、标题和版本信息一起滚动，按钮保持在正文之外。

## 更新日志格式

发版前准备 `deliverables/release-notes-v{version}-inapp.txt`，**每条说明独占一行**，与该版本更新日志的文案对应。现有 `scripts/package.py` 会按原有换行写入 `latest.json.releaseNotes`；JSON 中显示为 `\n`，客户端解码后逐行排版。可用空行区分段落、`##` 表示分组、`- ` 表示条目，例如：

```text
## 本次更新
- 修复部分机型进入照片编辑页时闪退的问题。
- 提升胶片画廊的加载速度。

## 升级说明
- 同签名版本可直接覆盖安装，保留图库与编辑记录。
```

客户端也接受普通多行文字、数字列表、CRLF/CR 换行与简单的粗体、行内代码。不会把中文句号或分号猜成条目边界，也不会执行 HTML、加载外部图片或链接。历史单段清单继续按单段显示；要分条须在下次发版源文案中给出真实换行，不能只修改客户端或把字面量 `\\n` 写进文本文件。

## 发布步骤

**每次发版只有一件事不能漏：`SpektraLens-v{version}.apk` 和 `latest.json` 必须挂在同一个 Release 上。** 缺清单时固定地址返回 404，老版本点「检查更新」只会看到「暂时无法检查更新」，链路等于没上线（v0.3.9 即如此）。发完按下面的清单逐项确认，不要以「APK 已上传」当作完成。

1. 只有用户明确要求发版时才递增 Gradle 的 versionName / versionCode；功能开发阶段不提前改版本号。
2. 从 0.4.0 起必须使用已有 SpektraLens 正式密钥生成 APK，不得更换密钥或用 debug 密钥发行。0.3.9 及以前的 debug 包已按批准的迁移说明处理，不能用正式密钥直接覆盖；0.4.0 及之后同签名、递增 versionCode 可覆盖安装。妥善备份密钥，不提交到仓库。
3. `scripts/package.py` 仍验证并复制既有 debug 构建，生成源码、交付包和 `deliverables/latest.json`。默认清单哈希来自该 debug APK，URL 仍使用正式资源名 `SpektraLens-v{version}.apk`，没有 debug 后缀。若实际发行另一个已签名 APK，使用 `python3 scripts/package.py --release-apk /path/to/signed.apk` 生成对应清单；此参数不会替代现有 debug 交付物。发布前确认 APK 内版本与当前 Gradle 版本一致。
4. 校对 latest.json 的 versionCode、versionName、SHA-256、sizeBytes、minSdk 与实际发布 APK 一致。按上文格式准备多行 releaseNotes，保留日志条目与换行；可加入按优先级排列的 HTTPS apkUrlMirrors，镜像必须是同一 APK。不要手填另一份包的哈希。
5. 创建 `v{version}` GitHub Release，将实际发行 APK 命名为 **`SpektraLens-v{version}.apk`**，与固定文件名 **`latest.json`** 一起上传；确认该 Release 被标记为 latest。清单 URL 为 `https://github.com/qing1989/SpektraLens/releases/download/v{version}/SpektraLens-v{version}.apk`。两个资产必须在同一个 Release：只挂 APK 会让 `releases/latest/download/latest.json` 返回 404。
6. 下载 Release 两个资源重新核对 SHA-256、大小、版本和签名。用已安装的上一版本真机测试检查、取消、下载、授权返回和系统安装确认；确认覆盖安装后照片、编辑记录和设置仍在。覆盖安装无需清数据或卸载。

发版后自检：

- [ ] Release 资产恰好包含 `SpektraLens-v{version}.apk` 与 `latest.json`，且该 Release 是 latest
- [ ] `latest.json` 的 versionCode / versionName / sha256 / sizeBytes / minSdk 与 APK 实际一致（哈希错会让用户下完就被自己的校验拒绝）
- [ ] 清单里的 `apkUrl` 指向本次 Release 的真实下载地址，镜像（若有）是同一份 APK
- [ ] `releaseNotes` 与本版更新日志对应，解码后每条一行；长文案在更新弹窗内滚动时按钮始终可点
- [ ] 用上一版本安装包实测：能查到新版本、能下载、能完成一次真实覆盖安装

清单必需字段：整数 versionCode、字符串 versionName、HTTPS apkUrl、小写 64 位 hex sha256。建议正整数 sizeBytes；可选整数 minSdk、字符串 releaseNotes、字符串数组 apkUrlMirrors。缺少 sizeBytes 时采用 512 MiB 硬上限；缺少 minSdk 不额外限制；缺少说明显示默认文案，缺少镜像仅尝试主地址。无效镜像忽略，关键字段无效则拒绝更新。清单最大 64 KiB，APK 最大 512 MiB，重定向最多五次且每一跳必须 HTTPS，连接/读取超时 15/20 秒。静默检查失败不弹窗，手动检查或下载失败可打开发布页；下载和安装仍必须由用户主动确认。

## 安装与生命周期

APK 只写应用私有 `cache/updates/{随机名}.apk`，每次候选源下载完成必须通过 SHA-256 校验；失败删除并尝试下一源，全部失败说明错误。下载支持取消，退出 Activity 时取消任务并清理缓存；系统可能回收缓存，安装前会再次校验，不存在的包不能安装。

首次安装更新需用户在系统设置授权「安装未知应用」。待安装哈希与缓存文件名保存在私有 preferences，返回后只续接一次；进程被回收后重建也可续接。返回时权限仍未授予，不再次跳设置，而是提示「尚未允许安装」并给出「重试」（复用已校验的缓存包，不重新下载）或「稍后」（删除该包，不留孤儿文件）。校验通过后使用 PackageInstaller.Session，API 31+ 明确要求用户操作；API 35 使用显式、可变 PendingIntent 接收安装结果，并通过 ActivityOptions 显式授予该回调所需的启动权限，再打开系统确认界面。不暴露 APK URI，不修改 ShareProvider。
