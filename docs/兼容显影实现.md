# v0.2.3 兼容显影与重建

GPU 初始化在厂商驱动中没有可取消的通用接口。把 JNI 调用放到 Java Future 并超时，无法真正中止驱动中的线程，也不能安全释放正在执行的 Vulkan command buffer。因此本版本将引擎放入两个不导出的私有进程：`:renderer_gpu` 与 `:renderer_cpu`。编辑器通过同 UID Binder 接口传递参数、Bitmap 和应用私有路径。

初始化先连接进程并确认其 PID 不等于编辑器 PID；GPU 创建上限为 15 秒，超时结束该私有进程，然后在新进程加载随包 CPU 库。v0.2.3 的自动模式也会在 OPPO 尝试新版 GPU 自检；用户手动选择的 CPU 模式会保留。CPU 初始化上限 90 秒。预览、RAW 解码和导出也有各自期限；进程死亡或超时会返回错误，原照片和参数仍存于编辑器的私有文件目录。

初始化过程记录加载数据、Vulkan loader、实例/设备创建、compute pipeline 编译、提交、自检 fence 等阶段。自检提交采用 8 秒 fence 等待；逾期直接结束一次性显影进程，避免释放仍在飞行的命令缓冲区。移动 GPU 补丁保留严格 math guard，并加入独立验证的 exact split 备选路径，没有放宽容差。普通运行的队列提交沿用原代码，由外层 IPC 期限处理卡住的进程。

CPU 模式使用固定 SwiftShader 实现相同 Vulkan/SPIR-V 路径；胶片测量数据与光谱模型保持原样，数值自检仍必须通过。内核在本机 CPU 执行，没有云端处理。小色卡的像素差比较仅是本次回归检查，不代表完整 Python/Metal 逐像素 parity，真机速度与内存边界仍需实测。

## 构建

普通 APK 构建使用 `android/app/src/main/jniLibs/{arm64-v8a,x86_64}/libvk_swiftshader.so`，不重新编译 LLVM。完整固定源位于 `third_party/SwiftShader-cddb5c91-source.zip`，SHA-256 和 commit 记录在 `THIRD_PARTY_NOTICES.md`；ZIP 包含该 commit 的全部已跟踪源文件，未包含 `.git`。

```sh
export ANDROID_HOME=/absolute/path/to/Android/sdk
python3 scripts/build_swiftshader.py --jobs 6
python3 scripts/build.py :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug
python3 scripts/device_tests.py --fetch-camera-fixture
```

需要 NDK 27.2.12479018、CMake/Ninja 3.22.1；脚本支持 macOS 和 Linux 主机，可通过 `ANDROID_NDK_HOME` 与 `CMAKE` 指定工具路径。可用 `--abis arm64-v8a` 只重建手机 ABI；`--source /path/to/checkout` 可使用已有源目录。默认解压源包，不需要 Git 子模块或额外联网依赖。替换源码后应清除对应 `.tooling/swiftshader-build-*` 构建缓存再重新配置。

使用 LLVM 10 Reactor、Release `-O2`、NDK API 29 与静态 libc++；关闭 ASTC、测试、基准和全部 WSI。上游 standalone CMake 未直接暴露 Android headless 平台，本项目选择 POSIX/Linux 的无窗口实现，仍由 Android toolchain 生成 Bionic ELF。构建中存在以下适配，均只作用于生成的 Ninja 文件或编译参数：

- 关闭通用源码的 `__ANDROID__` 分支，避免依赖系统私有 HAL/gralloc 头；不构建窗口/显示相关功能。
- 仅在 `Reactor/ExecutableMemory.cpp` 恢复 `__ANDROID__` 并取消 `ANDROID_NDK_BUILD`，选中它原有的 Android `MAP_ANONYMOUS` + `prctl` 路径。Linux 的 memfd 私有映射在 Android 应用域触发 `execmod` 拒绝，不能用于该 JIT。没有修改 SELinux、系统权限或全局设置。
- Bionic pthread 已在 libc，移除该 Linux 目标添加的 `-lpthread`。
- 对含空格的 version-script 路径进行 shell 引号处理；允许导出表中已关闭 WSI 的无实现符号，同时保留链接器的真实未解析引用检查。
- 链接使用 `-z max-page-size=16384`，兼容 16 KB ELF 装载对齐。真正 16 KB Android 设备尚未执行验证。

原始源文件保持原字节；重建适配写在 `scripts/build_swiftshader.py`，随源码交付。APK 许可目录及固定源 ZIP 保留相关第三方声明。

## 运行中的 GPU 恢复

GPU 显影调用遇到进程死亡、超时、Vulkan 或设备缓冲区范围错误时，`SpectralRenderer` 关闭 GPU 连接并创建 CPU 引擎。保存的最近一次 OPEN 参数用于重新打开 Bitmap、RAW 路径或普通原文件路径，然后重试当前 render/export 一次；CPU 错误继续返回给界面。未知胶片、参数等输入错误直接返回，不触发 CPU 重试。`closeImage` 清除恢复源，Activity 销毁清理连接。仅保留当前源引用，未复制照片到外部位置。

原尺寸普通图像经 `OPEN_FILE` 在私有显影进程内解码到可写 sRGB ARGB8888，再进入同一 JNI 管线，避免主编辑器创建并发送完整 Bitmap。导出后关闭图像；下一次预览仍按正常源引用重新打开。导出配方和底部标签使用实际后端，记录回退后的能力信息。
