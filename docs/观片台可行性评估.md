# SpektraLens 观片台可行性评估

状态：2026-11-22 已按用户确认的首版范围接入 Android 观片台，代码在 `LightTablePage.java`，随下一版发布。以下调研保留作为后续对齐上游的依据。

## 2026-11-23 · 编辑片边上台

- 编辑片边后可用「保存并返回」提交修改，再到「观片台 → 添加照片」选入。台面、放大镜、明室白和暗房黑海报使用同一张显影成品的透明轮廓。135 齿孔和 4×5 页片缺口能看到下层，银盐灰片基部分透光，正片夹纸面遮光，120 双 V 片门沿用画面像素。
- 胶片片边显影图在 `developed/<id>.png` 保存真实透明度。普通显影图继续用 JPEG。旧 135 JPEG 经原有孔位校验后临时上台，后台显影发布 PNG 后自动刷新。导出会核对最新显影文件，片边尚在显影时提示稍后再导出。
- 已定向的 JPEG 和 PNG 由 `BitmapFactory` 按需解码。添加照片网格继续走独立线程池与 LRU，台面高清图在后台替换占位图。海报底部铭牌沿用方案 1。

## 2026-11-23 Android 方案 A 首次落地记录（仅竖版 2:3 + 单行底栏）

- 入口：底部共享 3-Tab 悬浮导航「观片台」，与「首页 / 设置」真平级直接切换（切离即释放位图与底板内存，切回按最新图库即时重建）。
- 页面结构：纯黑暗房底色（`AppStyle.BG`）；顶栏去掉返回箭头，改为左对齐「观片台 + 精致计数微胶囊（`N / 12`，等宽数字）」+ 右侧 3 枚 36dp 暗房微圆图标按钮（`放大镜 / 整理 / + 添加`）与象牙白「导出」胶囊；仅支持竖版 2:3，底部预留 84dp 避让悬浮底栏。
- 底部上下文原位变形（零双层底栏）：打开默认处于浏览态（`selected = null`），底部由宿主展示共享 3-Tab 导航；点选某张照片时通知宿主隐藏 3-Tab，在底部同一物理位置替换为单行照片上下文条（微暖金细描边同心胶囊 `放大镜 / 旋转 / 移除` + 象牙白 `✓ 完成`）；开启 3× 放大镜时同样隐藏 3-Tab，底栏切换为 `[● 3× 放大镜 · 拖动查看] + [✓ 完成]`。点空白、点「完成」或按系统返回键逐级退出（关添加弹窗 → 退放大镜/取消选中 → 回到首页 Tab）。
- 照片来源与缩略图提速：读取首页图库顺序（最近导入优先），经 `MainActivity.lightTableSources()` 传入 `frame.params` 与解析后的胶片短名 `filmLabel`，精确识别 `135_black` / `135_warm` 边框、`edge_amount` 与海报印样胶片信息。添加面板两列网格，已上台照片标记「已添加」，最多 12 张；缩略图解码已从单线程 `io` 拆出至独立 3 线程 `thumbExecutor`，针对已定向的 `developed/<id>.jpg` / `thumbnails/<id>.jpg` 走轻量 `BitmapFactory`（`inSampleSize` + `RGB_565`）并配合 8 MiB `LruCache`（按文件修改时间失效），在 `dialog.show()` 之后派发并用弹窗存活态与 tag 校验（消除 `!isAttachedToWindow()` 丢图）；上台时先用缓存/快速缩略图秒铺占位，后台单线程 `io` 按 1280px 长边解码完整成品（含 135 透明齿孔）后无缝替换。
- 光学灯箱与质感：在 `onSizeChanged` 通过独立后台线程预烘焙物理灯箱底板（外缘微弱暖白环境溢光平滑融入 `#000000` + 接触暗边 + CNC 钛银阳极氧化拉丝铝框 + 滚圆倒角/亮棱/双频拉丝微纹/内嵌凹槽/暖光内唇回射 + `#FFFEFC` 通电漫射亚克力板微噪点与边缘暖衰减 + 顶/左 L 形 1·5·10mm `MULTIPLY` 蚀刻标尺与等宽厘米数字），拖动与放大镜 60–120fps 零额外底板重绘；已收拢 `TablePalette` 结构体便于后续扩展全应用明室主题切换。
- 照片呈现：移除强制 `5.5dp` 伪白卡纸边框；所有照片共享左上→右下世界光方向双层物理软影（偏移抬升软影 + 紧贴玻璃接触暗边 AO，拖动时自动微抬 1.024× 并拉长软影）、斜向醋酸片基光泽、以及琥珀金双层选中细描边（柔光晕 + 1.6dp `#E0B47A` + 0.5dp 内亮白线）；已显影的 135 胶片条经几何比例与 16 孔/14 片基采样双重校验后真实打穿透明齿孔（`DST_OUT`）并补暖白内壁背光微边，阴影与光泽经 `clipOutPath` 避开齿孔，绝不误伤普通照片高光。
- 放大镜：移除实心深棕框、暖金内环与白色十字准星，升级为预烘焙 3D 光学玻璃切边放大镜（柔方向浮影 + 1.80× 透明折射切边环 + 2.85× 镜心高清原图放大 + 左上弯月反光与穹顶光 + 右下厚玻璃暗部折射与暖焦散 + 棱镜微色散与锐利玻璃切棱脊/内外暗缝）；支持原位抓拖覆盖台面每一毫米，点按远处自动偏移在手指上方防遮挡。
- 导出确认与竖版品牌海报：点顶栏「导出」先弹底部确认面板（`AppStyle.SURFACE` / 26dp 顶圆角 / 等宽 48dp「取消 / 保存到相册」胶囊），内含 420×630 后台实时预览、「海报背景（明室白 / 暗房黑）」同心两段胶囊与「底部铭牌（应用图标、宣言与印样信息）」原生 `Switch`（默认明室白 + 开启铭牌，记忆上次选择，关闭则导出居中纯灯箱）。确认后全流程在后台线程渲染 1600×2400 JPEG（导出前自动补齐尚未解完的 1280px 高清图源，无白边双层阴影、全分辨率矢量 L 形蚀刻标尺、135 透明齿孔与醋酸光泽，不含选中框与放大镜）；底部铭牌采用方案 1（左：`ic_spektra_film_s_logo` 圆角投影图标 + `SpektraLens` + `暗房里没有过去，只有正在发生的影像`；右：胶片印样档案签 `主胶片 [· +N]` 与 `YYYY.MM.DD · NN FRAMES`，无已编辑胶片回退 `CONTACT SHEET`），写入系统 `Pictures/SpektraLens` 并保留缓存副本供完成弹窗一键分享。

## 结论

可以在 Android 版实现。建议作为独立的观片台页面开发，继续使用现有显影引擎提供照片成品，再完成台面绘制、照片摆放、查看和合成导出。

实现基础体验不必整体升级 SpektraLab。上游的摆放、坐标、手势和尺寸算法可以参考或移植；上游界面与 GPU 绘制使用 Swift、UIKit/SwiftUI、Metal，需要在 Android 端重新接入。高清读取、片边透明度和大尺寸合成需要专门设计。

| 功能 | 已核实的行为 | 主要证据 |
| --- | --- | --- |
| 虚拟灯箱 | A4、A5、A6 台面，可选择横向或竖向；照片按胶片尺寸换算为毫米摆放 | S1、S4 |
| 自由摆放 | 移动、旋转、层叠；摆放时寻找空位；整理布局、散放；移动或旋转的照片移到上层 | S1、S2 |

| 成品图源 | 读取各张照片的已显影结果与编辑信息，图源不够清晰时请求更高分辨率；新编辑会改变缓存身份 | S5、S6、S7 |
| 保存布局 | 独立 JSON 保存照片 ID、位置、角度、层级、台面尺寸和朝向；图库删除照片后清理失效引用 | S8 |

上游模型允许最多 99 张照片。这不是 Android 端可以直接承诺的性能指标；本项目应根据内存预算与设备实测确定容量及画质降级规则。

## 与现有 SpektraLens 的衔接

### 已有能力

- `MainActivity.Frame` 和 `library.json` 已有照片 ID、原文件、名称与编辑参数，可作为观片台照片来源。
- `saveActiveFrame()` 已保存每张照片的编辑配方，可以在不改变当前编辑状态的情况下，为某张照片建立显影任务快照。
- `SpectralRenderer` 已有 `openFile/openRaw`、有界预览和原尺寸导出接口，显影在独立进程完成。
- 已有照片预览、手势处理、写入系统相册、图片分享与系统触感实现，可以复用相关基础设施。

证据位置：

- `android/app/src/main/java/app/spektrafilm/MainActivity.java`：`Frame`、`loadLibrary()`、`saveActiveFrame()`、`export(ExportOptions)`。
- `android/app/src/main/java/app/spektrafilm/SpectralRenderer.java`：`openFile()`、`openRaw()`、`render()`、`exportImage()`。

### 必须补齐的部分

1. **观片台的数据与交互。** 增加台面坐标、照片位置/角度/层级、命中检测、自动排列和本地布局保存。台面缩放和照片移动/旋转要区分，手指数变化时重设手势基准，避免画面跳动。
2. **按照片成品建立独立缓存。** `HomePhotoImages.storeDeveloped()` 目前保存最长边 1024px、JPEG 88 的首页小图，可以用于快速占位，不能承担放大镜和高清合成。应按可见尺寸分级加载，清晰图就绪后替换旧图，不在每次拖动时显影。
3. **沿用每张照片自己的编辑结果。** 观片台需要保存和展示用户完成的曝光、曲线、HSL、相纸、颗粒、日期、片边等。现有胶片选择画廊只显示原片套用默认胶片风格，两种缓存必须独立；观片台不能拿 `filmThumbs` 直接代替成品。
4. **真实片边与透明遮罩。** 当前 `edit_pipeline.cpp` 的 `FrameLayout` 按照片短边百分比计算片边，`borders()` 把齿孔画为浅色矩形。上游依照胶片物理尺寸与几何计算外形，再进行透光合成。若要达到相同效果，需要补充片边几何和遮罩；不能仅把现有 JPEG 当作带透明孔洞的底片使用，也不能按画面亮度抠孔，以免伤到照片高光。
5. **高清合成与内存预算。** 不能同时装入多张原尺寸位图再创建一张巨型 Bitmap。应逐张准备足够清晰的成品图，限制内存驻留，对更大输出采用分块/分行合成与编码；Android 的编码路径需要单独实现和验证。
6. **独立任务与取消。** 把依赖当前 Activity 状态的参数构造整理为照片任务快照，逐张排队，保留主预览优先；取消和失败不能污染当前照片、参数、`openedSource` 或画廊缓存。
7. **布局生命周期。** 独立文件保存台面，不把摆放动作写入照片编辑历史。照片重新编辑时更新对应成品缓存；照片移除、应用重启、旋转、低内存与导出中断均需处理。

## 建议首版范围

这是产品建议，尚未经用户确认或进入代码阶段：

- 从首页进入独立「观片台」，从「最近的底片」多选已导入的照片。
- 保留黑灰与橙色操作风格，中央为白色灯箱；工具继续采用简洁文字按钮。
- 支持台面尺寸/朝向、移动、旋转、层级、移除、整理、台面缩放和本地保存。
- 预览使用每张照片的完整编辑结果；显示自身片边，片边增强与透明孔洞单独评估，避免改变现有单张导出。
- 先提供日常分享用的整版 JPEG/PNG 输出；具体像素档位和照片上限在设备验证后确定。
- 放大镜、透明灯箱导出和上游最高 5000px 短边输出可继续实现，但需在高清图源与内存预算完成后验收。
- 如增加品牌海报，使用 SpektraLens 自己的排版与素材；上游署名在许可与关于页中继续保留。

照片、配方、布局和导出均在本机处理。此功能不需要新增网络用途、账号、更新 SDK 或遥测。

建议先确认手机端原型，重点区分「移动整张台面」与「移动一张照片」，再确定首版范围。当前版本和签名不作调整。

## 实施后的验收重点

- 逐张照片与单张编辑页最终效果相符，图源变更后缓存正确更新。
- 台面操作不触发不必要的显影、不改变原有编辑参数或胶片画廊默认配方。
- 一指/双指切换、旋转吸附、层叠命中、缩放边界不跳动。
- 缩小显示保持颗粒自然，放大按需提高清晰度，避免将首页小图强行放大。
- 多张大尺寸 JPEG/RAW、低内存、后台切换及导出取消不会造成界面进程崩溃。
- 输出与台面布局一致，照片细节、颜色与透明边缘正确，导出尺寸和文件格式真实可核对。
