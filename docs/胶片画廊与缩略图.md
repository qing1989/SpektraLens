2026-11-12，在 `feature/in-app-update` 合入 `feat/film-gallery` 的 `c71b1ad`，对应 cherry-pick 提交 `a458731`。版本保持 `0.4.0 / 19`。

**2026-11-12 已按用户最终确认的停留规则重做：每次导入落「全部」第一张、默认胶片为目录第一张；点中间卡片不滑动，只有点视口最左/最右那张且外侧还有胶片时才跟滑一格；各分类各自记忆停留位置。大图始终按当前胶片和用户全部调节渲染。实机已复验。**

## 产品约定

- 胶片选择使用 88dp 方形照片缩略图，横向滚动，标签不加底，选中标签为橙色。
- 选中框为 2dp 白色描边，与照片共用矩形和 16dp 圆角；描边向内覆盖，保持项目三档圆角。
- 缩略图取当前照片经过对应胶片显影后的真实结果，只渲染可见范围及 60dp 缓冲。
- **用户于本轮进一步明确：画廊只基于导入原片与各款胶片的默认风格。曝光、曲线、HSL、相纸、颗粒、边框和日期等二次调节仅影响主预览，不传入画廊，也不触发其重新渲染。此要求取代原交接文档第八节第 6 项的“拖动曝光后全部重算”。**
- 同系列胶片效果接近是当前引擎特性，保持真实结果，等待用户决定展示方向；不调整模型、配置数据或人为增强差异。

## 四条引擎约束

1. 每张缩略图均重新打开当前原片。普通照片使用 `openFile`，RAW 使用 `openRaw`；没有文件的内置 bitmap 才回退到 `open`。不通过单改 `film_stock` 复用已经固化配置的输入。
2. 缩略图的 `preview_long_edge` 为 800，不使用引擎下限以下的参数；低分辨率输入不强制放大。
3. `product_defaults` 只在 open 参数中，render 参数单独构造，不能包含此字段。
4. 打开缩略图前及结束后（包含失败路径）清空 `openedSource`，让主预览重新打开它自己的胶片配置。
5. 普通照片的画廊 `openFile` 将解码长边限制为 1024px。该解码结果留在私有显影进程，按文件路径、大小、修改时间和目标长边复用；每款胶片仍重新执行 `open + render`，不能把复用缓存误认为可以省略逐卷 open。

负片/反转片分别使用既有的印相/直接扫描参数和默认联动相纸；缩略图使用独立中性配方，RAW/JPEG 沿用各自的初始测光策略。render 的二次编辑参数为空，不套用当前照片的用户调整；不修改引擎中的胶片效果。

## 缓存与调度

- 缓存指纹只包含照片载入代次、原文件路径、预览 bitmap 身份和引擎启动代次。更换照片或重启引擎时重新准备缓存，编辑参数和当前选中胶片不进入该指纹。
- 引擎仍按 800px 下限完成显影，返回编辑进程前再按 88dp 卡片和屏幕密度缩到 256～512px。缩略图缓存使用最近最少使用顺序，总预算固定为 16 MiB；淘汰前先解除对应 ImageView，再回收位图。
- 缓存与 View 只在 UI 线程更新。旧 bitmap 先从 View 解绑，再回收；过期渲染结果不会挂到新照片或新参数的卡片上。
- 缩略图使用现有单线程 worker，每次只排一张；有主预览请求时暂停后续缩略图调度，主预览完成后再补。
- 切换其他工具、返回首页或导出期间不继续排缩略图；导出结束、引擎就绪和主预览完成时仅补尚未生成的可见项，不重算已缓存图片。失败项在当前指纹下暂停重试，照片或引擎代次改变后重新允许加载。

## 性能优化与证据

此前 `OPEN_FILE` 没有按画廊输出尺寸限制解码，4000×3000 JPEG 会以 12MP 位图进入光谱引擎；800px 只限制最终返回图，未阻止完整分辨率解码和中间计算。2026-11-13 改为 1024px 有界解码并在私有进程复用，随后把 800px 显影结果缩到卡片尺寸再跨 Binder 返回。

Android 15 / API 35 arm64 模拟器、CPU 兼容显影、4000×3000 JPEG、连续四款胶片的对照：

| 路径 | open 合计 | render 合计 | 四款合计 |
|---|---:|---:|---:|
| 优化前：每款完整解码原图，返回 800px | 2792 ms | 5858 ms | 8650 ms |
| 优化后：复用 1024px 源图，返回 384×288 | 136 ms | 1998 ms | 2134 ms |

本组合基准约快 **4.05 倍**。同一胶片分别以完整原图和 1024px 有界源图显影、再缩到 384×288 后，RGB 平均通道差为 **0.187/255**；这是缩略图尺寸下的可接受差异。结果来自模拟器，实体手机 GPU 的实际绝对耗时会不同。

## 验收方式

`FilmGalleryInstrumentedTest` 使用两张不同的本地合成照片，验证方形卡、白框/无底标签、当前原片路径、首屏加载范围与滚动补图、实际拖动曝光及其他二次调节后缓存保持不变、换照片才失效、主预览与重新 open 的对照，以及未就绪守卫和真实引擎重启后自动补图。测试不要求不同胶片的结果拉开视觉差异。

保留 `EditorLayoutInstrumentedTest` 的三个用例，检查九个工具页的固定预览/面板高度、滑杆端点和底部渐隐。

验收在独立 `Gallery_API35` arm64 模拟器会话中执行，不卸载原 `BookVoice_API35` 会话中的正式包；开发构建不更新 `deliverables/SpektraLens-v0.4.0.apk`，也不发布 Release。
