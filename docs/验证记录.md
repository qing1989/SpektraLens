## RAW 与原尺寸证据

1. 合成 DNG：256 × 192，单 Bayer CFA IFD，没有 JPEG、缩略图或第二预览 IFD。Android 上通过 LibRaw 得到 128 × 96 预览，再从传感器数据重新解码并导出 256 × 192 PNG16。独立 TIFF 解析确认输入只有 CFA 图像，证明没有拿内嵌预览替代 RAW 解码。
2. 真实相机：rawpy 固定 commit 测试目录中的 Nikon D3S `iss030e122639.NEF`。元数据读出 Nikon / D3S、ISO 3200、28 mm、f/1.4；384 像素预览与真实光谱显影均通过。另一次从原文件解码后，实际导出 **4284 × 2844 JPEG**，与 LibRaw 识别的原始有效尺寸一致。
3. 3072 × 2048 合成输入实际光谱显影并导出 3072 × 2048 PNG16，证明没有沿用 2560 上限。

真实相机样片只作本地验证，未包含在 APK 或源码 ZIP 中；来源、固定 commit 与校验值写入 `scripts/device_tests.py`。这一项不能证明所有 `.RAF`、`.ARW`、`.CR3` 等机型均可用。

## 输出文件独立校验

从应用私有目录取出实际导出文件，使用独立 Python/Pillow/tifffile/标准 PNG 解析验证：

- 相同显影与编辑参数导出的 PNG16、TIFF16，解码后 RGB 样本 **逐像素完全一致**。
- PNG 所有 chunk CRC 通过；IHDR 标明每通道 16 位、RGB。TIFF 的 BitsPerSample 为 16，含 ICC；JPEG 含 sRGB ICC。
- 3072 × 2048 PNG 的 99.60% 通道样本低 8 位非零，确认不是把 8 位结果简单乘 257 后包装成 16 位。
- 在相同输入尺寸下，PNG16 转成屏幕 8 位后的像素与实际编辑预览每通道差值不超过 1。

该预览一致性断言使用同尺寸、关闭随机质感的输入。不同分辨率下的采样、颗粒和光晕可以有差异，未声称低分辨率预览与原尺寸结果逐像素相同。

# v0.2.1 普通照片导入卡住修复

日期：2026-11-01（Asia/Shanghai）。用户报告 OPPO N6 从本机相册导入普通照片后一直显示“正在读取照片”。当前没有连接该实体手机，以下为代码诊断和模拟器复现结果，不代表已在 OPPO N6 上确认恢复。

## 可复现的问题与改动

旧版 `importUri` 与 Vulkan 显影共用 `worker` 单线程执行器。测试把该执行队列阻塞，再导入本地 JPEG；旧版在 4 秒观察期内无法建立照片预览，确实停在“正在读取照片”，专项测试失败（`import-repro-old.log`）。这是一个能够产生相同现象的已确认缺陷；没有实体机日志，不能据此断言它是该 OPPO 手机的唯一原因。

v0.2.1 的普通照片导入改用独立 I/O 执行器，读取、缩小解码、缩略图与保存均不等待显影队列。JPEG（含 Ultra HDR JPEG）、PNG、HEIF/HEIC、AVIF、WebP 等先按文件头识别，跳过 LibRaw 探测；8 位 sRGB 预览与后续光谱渲染分开。首页不再自动显影示例。RAW 的原始解码和引擎仍保持原有串行约束，没有并发操作 Vulkan 会话。

新增独立导入任务、唯一临时文件、取消信号与关闭读取流。界面显示信息读取、相册打开、原文件复制字节数、解码与保存阶段，底部可取消。普通导入阶段 30 秒无进展会结束等待，RAW 阶段 120 秒；失败/取消保留上一张照片。显影开始后显示“照片已读取”，超过 30 秒会显示显影响应较慢，并提供诊断入口，不再与文件读取混在一起。启动完成的旧照片回调不能覆盖新导入照片。

`files/last_import.json` 记录型号、Android API、阶段、字节数、耗时及结果；关于窗口的“导入诊断”可以查看和复制。它不采集照片像素、原 URI 或网络凭据，不自动发送数据。

# v0.2.2 引擎启动、独立进程与 CPU 兼容显影

验证日期：2026-11-01（Asia/Shanghai）。用户诊断设备为 OPPO PLP110 / Android API 37；10,716,747 字节 `84.jpg` 在 200 ms 内完成读取及保存，引擎仍显示准备中或不可用。由此确认等待发生于后续引擎阶段；旧版没有逐调用初始化日志，不能据此断言具体阻塞在哪次厂商 Vulkan 调用。

## 改动

- 编辑器、GPU 显影和 CPU 兼容显影分别运行于独立进程。GPU 启动超时或异常会结束该进程并尝试兼容显影；OPPO PLP110 且 API >= 37 的自动模式直接使用 CPU。
- CPU 库来自固定 SwiftShader 源码，在本机执行相同光谱 SPIR-V；保留 math guard、数值编译设置、测量数据和原始着色器，没有以简单滤镜代替显影。
- 初始化阶段、自检、设备/驱动、PID、回退原因写入可复制诊断。初始化和 RPC 各有期限，失败提供重启入口。预览进程退出不会清空编辑器内的照片或参数。
- 关闭连接先解绑，再结束子进程；后续连接等待旧 Binder 死亡。处理 Activity 快速重建遗留会话，连续重试不能复用已初始化的旧引擎。主 Activity 复用已有任务，分享输入无需等待引擎就绪即可读取普通照片。
- 细节、固定源码和重建命令见 `兼容显影实现.md`。上游 SpektraLab 文件与 SwiftShader 源文件均保持原字节，适配由 Android 层和构建参数完成。
