# 照片预览与显影资源校验

日期：2026-11-04。本轮继续打磨现有胶片效果与照片预览；GitHub 上传已按用户要求暂缓。

## 安装包决定运行时显影资源

此前启动只判断 `engine_267ee243_mobile_v3/.ready` 是否存在。这个标记没有记录内容，覆盖安装后，即使安装包更新了 shader 或引擎资源，也可能继续使用旧缓存。它是代码中确认的升级隐患，不是对用户手机上某次胶片观感的归因。

现在 `EngineResources.prepare` 从实际安装包逐文件计算 SHA-256，结合相对路径生成资源指纹，并核验缓存中的全部对应文件。内容一致时复用；旧标记、文件缺失或损坏、额外遗留文件都会触发重新准备。完成全部复制与校验后才写就绪标记，中断或失败不会留下可以直接信任的标记。

这个流程位于已有后台初始化队列，操作范围仅为应用私有的引擎资源目录。图库、照片副本和编辑记录不参与清理。胶片与相纸的测量数据未修改。

## 缩放跟随手势焦点

双指缩放同时处理缩放比例和两指中心的移动，把手指下的图像位置留在同一位置；触及画面边缘时继续限制平移，避免照片整体移出屏幕。双击以点击位置放大，再次双击复位。缩放范围沿用 1–6 倍。

对比模式中，一次双指手势持续到最后一根手指离开。捏合后剩余手指的移动不会立即变成对比分界线拖动；重新落指后仍可正常拖动分界线。父容器的触摸拦截在抬指或取消时释放。

本次没有改变预览像素上限或导出分辨率。放大仍是当前预览的显示缩放，不宣称加载了原图级细节。

## 重启后打开最近底片

v0.3.3 补充：应用启动时在首页恢复原图，显影延迟到进入编辑器。此前点击与当前记录相同的底片会直接返回，遗漏显影请求；现在在该照片尚无成片预览时发起显影，同时保留它自己的编辑参数。

新增工作流测试实际导入照片、修改曝光、退出并重建 Activity，再点击首页第一张底片；检查成片预览、可用的导出按钮与原有编辑记录。修复前该测试因无法生成预览而失败。

## 验证

修复前，在旧安装包上运行三个真实触摸回归，全部出现预期失败：双击后焦点红通道由 179 变为 153，捏合后由 179 变为 164，捏合结束后的单指移动把测试位置从显影侧移到了原图侧。断言基于触摸前后的实际绘制像素，不读取内部缩放状态。

修复后，3 项照片手势与 2 项资源校验测试全部通过，耗时 0.702 秒。资源测试使用实际安装包内容，覆盖旧空标记、旧 shader、遗留文件、有效文件复用，以及长度未变的文件损坏。一次模拟器检查的资源迁移耗时 136ms，完整校验后复用耗时 75ms；这不是实体手机测速。

本地开发构建与 Lint 成功，0 个错误、7 条既有提示。原始日志位于忽略的 `.tooling/effect-audit/preview-*.log`，不包含在公开源码中。启动与导入/导出整体验证结果另见[验证记录](验证记录.md)。

最终完整测试 **55 项全部通过，101.316 秒**，包括原有独立 Metal 胶片参考、RAW、原尺寸输出、导入/参数复用、故障恢复与当前界面检查。随后正常启动 App、导入公开示例照片，从实际应用私有目录读取运行时资源，核对 **68 个引擎文件全部与当前安装包逐字节相同**，就绪指纹也一致。验证环境为 Android 15 / API 35 arm64 模拟器，未连接 OPPO 实体手机。
