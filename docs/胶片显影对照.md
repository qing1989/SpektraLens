# 胶片显影核对与自动测光默认值

2026-11-03；本次只修改自动测光默认值和回归验证，不重新生成交付包。当前工作区以新导入默认关闭为准，此前交付 v0.3.2 的默认开启行为保留在历史记录中。

## 结论与修改

1. 自动测光默认改为 **关闭**。用户主动开启后，初始方式仍是 **中央加权**。
2. 开关默认值和送给显影引擎的实际 `auto_exposure` 参数一起核验。普通新导入回到关闭，取消导入不改变上一张；已有照片保存的手动选择、导出后“再编辑一张”的明确参数复用保留。
3. 在已处理的 JPG/PNG 上，自动测光会按中灰重新决定曝光；它会改变照片本来的亮暗意图，也会改变胶片曲线的落点和反差。这不是胶片配置被替换，但不适合默认作用于用户已处理的照片。
4. 对三个主要显影上游、输入与输出色彩空间、胶片/相纸配对、正片直扫、曝光补偿和 GPU 输出做了核对。在本次固定测试下，没有发现能解释大幅亮暗异常的胶片模型或通道错位。

## 测光为何改变观感

使用相同 Portra 400、默认相纸与中性调整，仅切换自动测光。表中“均值”是输出 RGB 编码值平均值，范围 0–255；测试为合成均匀灰场，不是实拍照片的质量评分。

| 输入灰场 | 关闭时输出均值 | 开启后应用的曝光 | 开启后输出均值 |
|---|---:|---:|---:|
| RGB = 64，原本较暗 | 41.00 | +1.844 EV | 117.33 |
| RGB = 220，原本较亮 | 200.67 | −1.960 EV | 117.33 |

两个亮暗意图不同的输入被测光拉到接近相同的中灰，这是亮暗异常的直接机制。实际照片的变化取决于内容；内置山景测试只得到 −0.046 EV，并不是每张照片都会变化两档。

## 独立数值对照方法

- 输入为 CC0 合成色块、肤色/植被/天空代表值和灰阶，96 × 64、编码 sRGB；避免只测线性输入造成的色彩盲区。
- 20 款胶片逐一取实际 `target_print`；反转片走 `scan_film=true`。统一输出编码 sRGB、35mm 画幅宽度参数 36mm，产品曝光语义相同。
- 基础对照关闭测光、颗粒、光晕和随机相纸炫光，隔离主链路。另加曝光增/减、密度曲线、光晕和显式中央加权测光，共 25 组 Android/Metal 配置。
- Python 使用原始上游自己的 `simulate`，只对齐输入/输出、胶片/相纸与上述开关；`print_exposure_compensation=false` 对应桌面产品的 `product_defaults=true`，不是修改数据。
- Metal 参考运行于 Apple M4。此机器没有离线 `metal` 编译工具，所以仅在临时副本中把加载 metallib 改为 `newLibrary(source, options)`，合并原始 shader 文本并设置 Safe math / Precise functions；原始数值代码和资源未变，原生数学探针通过。Android 源码及上游 checkout 未应用该加载适配。
- Android 使用实际 APK 中的 JNI、Vulkan shader 和导出器。新测试每次重新复制 APK 资源，不依赖历史 `.ready` 缓存；使用独立 Metal 结果作参考，避免同一 Vulkan 路径互相证明。

20 款 Python/Metal 的峰值为 `1.415e-5`，在上游 `3e-5` 的参考线内。Android/Metal 的 25 组可见 8 位输出最大相差 1 个编码值；16 位导出的峰值为 15/65535，约 0.000229，平均值更小。**这仍未达到上游 Metal/Python 的严格 `3e-5` 峰值参考线，不宣称 Vulkan 已完成全精度逐像素 parity。** 从本次幅度看，这类细微数值差异不足以解释明显的亮暗变化。

本比较统一为 sRGB 以隔离引擎。桌面完整工作流在 ProPhoto RGB 中调色、再输出其他色域；Android 当前在 sRGB 输出上调色，强饱和色与大量调色不保证完全相同。随机颗粒分布、高分辨率全部空间效应、OPPO GPU/HEIC 厂商解码和 RAW 与 Core Image 的色彩匹配也不由本组小图证明。

- 新的“默认关闭”测试先在旧 APK 上失败，再在修改后的 APK 上通过；验证 UI 开关、实际引擎参数、手动开启和下一张普通导入。

- `FilmParityInstrumentedTest` 包含 25 组独立参考；`WorkflowInstrumentedTest` 保留普通导入、显式参数复用、取消不泄漏、成功按钮等测试。
- 数值明细见 [胶片显影对照.json](胶片显影对照.json)。本地原始日志和 16 位观测文件保留在 `.tooling/effect-audit/`，未改变历史交付文件。

在有正常桌面 Metal 构建的 macOS 上，可使用上游自己的 dylib 重新生成基准：

```sh
# 使用具备 Metal 编译工具的 Xcode 环境；NumPy 只用于测试参考生成
(cd SpektraLab && engine/build.sh dylib)
python3 scripts/generate_film_reference.py \
  --library SpektraLab/engine/build/libspektrafilm_engine.dylib \
  --resources SpektraLab/engine/resources
python3 scripts/build.py -PpublicBuild=true :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug
python3 scripts/device_tests.py
```

生成器拒绝 Vulkan 库，并要求 Metal 的 Safe math 探针通过。26 个输入/参考 RGB8 文件已用随项目生成器重建并逐字节核对。参考输出的模型来源、许可与纯测试用途见基准目录 README；没有改写原有胶片或相纸材料数据。
